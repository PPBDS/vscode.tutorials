We need a quick tutorial for creating a second GitHub account.

There are a couple of tricks that we need to teach before milestone 4, either in current tutorials or in a special 'tricks' tutorial. Key topics:

  * Running `connect-repo' several times. You can actually just have a codespace named `Tutorials` and then use it for tutorials. Each time you run connect-repo, it makes a new folder in /workspaces/, and then pops the session into it. It is OK if you have a dozen different folders under /workspaces.

  * Exploring /workspaces. Students don't need to be experts in the terminal. But they should be able to explore /workspaces. As a side note, maybe the prompt should include the GitHub account name. That would be a reminder of which account they are using. Maybe we should guide them that their second account should be account.name-tutorials. This way, they will automatically know where they are.

  * Renaming repos. This should walk a student through the creation and then renaming process. Key to explain the need to push everything first and then run connect-repo. Note that it is good practice to delete the /workspaces/old-name directory since it no longer connects to anything. But, at the same time, it does not matter because connect-repo will make the new folder, corresponding to the changed repo name, without complaint.

  * Show how to find/open a file like 'devcontainer.json' even though it is not in the current directory.

## Tutorial Edits

Need to ensure that, by the time we finish the core VS Code tutorials that students are very comfortable with repo, .gitginore, QMD and so on. That is, we want to guarantee that all later tutorials can start with one question that starts (and states) from the assumption that you are in a repo named `x` and which tells you to set up a QMD, .gitigore with *_files, commit/push. And then the rest of the tutorial just has the student telling AI what to do with the QMD.

But, at the same time, we don't want to overwhelm them during week 1. So, we need to bring things in slowly.


We can split AI into two parts. In Getting Started and the Introduction, we just use GitHub Copilot. We know it will always be there and will always work for at least a few questions. Then, later, we can learn how to operate something like Antigravity from the command line.
